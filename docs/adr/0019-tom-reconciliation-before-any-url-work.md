# ADR 0019 — `url-lock.csv` is generated from a T.O.M. export; no URL work proceeds before the diff closes

- **Status:** Accepted, 2026-08-21
- **Deciders:** S. Le Boulanger
- **Related:** ADR 0003 (URLs are frozen on three axes), ADR 0015 (VG Wort operations), ADR 0012 (removal of the numeric tag terms), ADR 0017 (`topic` reclassification), ADR 0014 (new exam pages)
- **Blocks:** P0.8 (freeze the URL space), P3.2, P3.3 and P3.4a (the flat → leaf-bundle conversions), and every re-slug in the programme

## Context

The repositories are authoritative for which URL a Zählmarke **renders on**. They are not authoritative for — and cannot know — which URL that mark is **registered against** in T.O.M. Those are two different facts, and there is direct, measured evidence that they may have diverged across most of the corpus.

**The migration.** All three live sites migrated Quarto → Hugo on **2026-05-06**, replacing `.html` URLs with pretty URLs and leaving `aliases:` behind on **405** `efl` pages, **202** `fle` pages and **80** `daf` pages, of the shape `/track_e_kl09/units/unit06_interview-and-portrait.html`.

**The dates.** **399 of `efl`'s 402 marks are dated `registered_at: '2026-04-30'` — six days before the migration.** The remaining 3 are dated `2026-07-22`, as are all 68 of `daf`'s.

**The keys.** Every `efl` mark still records `qmd_path: appendices/common_errors.qmd`, naming its Quarto source. The header of `efl/data/vgwort.yaml` states in as many words that the file was generated by `_scripts/migrate_vgwort_to_data.py` from the Quarto-era manifest and re-keyed onto Hugo pretty URLs — that is, the **repository side** was re-keyed by a script, which is the only side a script in the repository can reach. `fle/vgwort-manifest.csv` holds 193 rows keyed on `qmd_path`, carried into Hugo verbatim.

**The mechanism that makes this cost money.** Hugo's built-in alias output is a bare `<meta http-equiv=refresh>` stub. It carries **no pixel**. `efl/_scripts/verify_rendered_pixels.py:28-30` skips alias pages by design, and correctly so — there is nothing on them to verify. An alias preserves the reader's link. It does not preserve the income.

**The exposure, stated exactly.** **Up to 592 marks are in question** — 399 `efl` plus 193 `fle` — and **229 are presumptively sound**: 3 `efl`, 156 `fle` exams, 2 `fle` data-file entries and 68 `daf`, all dated `2026-07-22`, after the migration. If the 592 are registered against the old `.html` URLs, they have been earning nothing since 2026-05-06.

**The repository cannot answer the question.** The `registered_at` dates *might* postdate a T.O.M.-side correction that the repository never recorded. Nothing on disk distinguishes that case from the bad one. Only the T.O.M. account can.

**A second dependency rides on the same export.** The 349 `fle` front-matter marks carry no `registered_at` anywhere in any repository — `grep -c registered_at fle/data/vgwort.yaml` returns 2. Gate C1 requires that field on every entry, so migrating those 349 into `vgwort/marks.yaml` would block `fle` permanently on the day it lands unless the dates come from somewhere. They exist in no repository. They come from the export.

## Decision

**`vgwort/url-lock.csv` is generated from a T.O.M. export, never from a sitemap. Until the reconciliation diff closes, nothing that changes a URL proceeds.**

**The reconciliation, in order.**

1. **Export the registered URL for all 821 codes from T.O.M.** to `~/vgwort/tom-export-2026-08-21.csv`, outside every repository. This is manual portal work with external latency; it is booked as an external dependency, not a repo task, and it is started on day one for that reason.
2. **Build all three sites and diff the export against each `sitemap.xml`**, producing `vgwort/tom-diff.csv` with schema `code,repo,registered_url,rendering_url,status` and `status ∈ {match, alias-only, absent, unregistered}`.
3. **Dispose of every `alias-only` row.** If VG Wort permits a URL edit on an already-registered work, correct the T.O.M. record — this is free and preserves the code. If it does not, the row enters the ADR 0015 re-key protocol, executed in that repository's Phase 3 branch, **never piecemeal**.
4. **Record the finding, whatever it is**, in `.github/docs/vgwort-operations.md` and against ADR 0015. If the export shows all 821 already pointing at Hugo URLs, that is a two-line entry and the programme proceeds unchanged — but it proceeds on something *known* rather than assumed.

**If T.O.M. offers no bulk export**, hand-sample twenty codes spread across the three repositories and across both `registered_at` dates. Twenty is enough to answer the only question that matters, which is a yes/no: was the Quarto-`.html`-to-Hugo-pretty-URL migration reflected in the registrations. A negative answer converts this from a reconciliation into the largest single revenue action in the programme.

**Then, and only then, the freeze.** `vgwort/url-lock.csv` carries the schema `url,code,registered_url,first_seen,content_sha` and is committed to `efl`, `fle` and `daf` — expected 402 + 351 + 68 = **821 rows**. The `url` column is populated from the export. Rows whose registered and rendering URLs disagree are written with the **T.O.M. URL** and `status: pending-rekey`, and are cleared in that repository's Phase 3 branch under the re-key protocol. From that moment gate A3 blocks any pull request that would orphan a mark — **including pull requests made by this programme**, which is the point of freezing rather than documenting.

**What is blocked until the diff closes**, named so nobody has to infer it: P0.8; the flat → leaf-bundle conversions in P3.2, P3.3 and P3.4a; the removal of `efl`'s 816 numeric Bildungsplan codes from `tags:` and the roughly 40 taxonomy terms that deletes (ADR 0012); the `topic` reclassification (ADR 0017); and any re-slug anywhere in the org.

**What is not blocked:** work that creates URLs rather than moving them, and work that touches no URL at all. `daf`'s 60 new exam pages under ADR 0014 mint new URLs and put no existing mark at risk. Content edits — the exam transfer, the Activate steps, the answer-key relocations — change a page's characters and never its address, so C6's count moves and A3 never fires.

**Acceptance.** `vgwort/tom-diff.csv` exists in all three repositories and its `alias-only` plus `absent` row count is either **0** or fully enumerated with a named disposition per row. `url-lock.csv` totals exactly 821 rows across the three files; every `code` is a unique 32-hex token appearing in exactly one repository (`sort | uniq -d` empty, org-wide); every `url` resolves in the corresponding built `sitemap.xml` or carries `status: pending-rekey`; and `bin/kit urldiff`, run against an unmodified checkout, produces an empty diff — proving the lock file agrees with the site it was generated from **before** it is ever used to block anything.

## Consequences

- **Status as of today: blocked.** Phase 0 executed on 2026-08-21 closed its other items — the `fle` audit gate, the deleted `regen-materials.yml`, the eager `ressources` pixel with its `<head>` preload, the move of all six Hugo repos off the deprecated `.Site.Data` to `hugo.Data`, and `actions/setup-go` with `go-version-file: go.mod` across all eight workflows. The export is external portal work and has not returned. Every item in the blocked list above waits on it.
- **The worst case is that several hundred euros a year have already been silently forfeited since 2026-05-06** — more than three months as of today. It costs half a day of portal work to find out. That asymmetry is the whole argument for doing this first.
- **If a bulk URL edit is not permitted, up to 592 marks enter the re-key protocol**: a new code drawn, bound and registered for each affected URL, the old code retired in the ledger with a reason, and both lock files updated. That is executed per repository inside its Phase 3 branch, so the diff a reviewer reads is one coherent change rather than a trickle of mark movements across unrelated pull requests.
- **A mark and its URL move in the same commit or neither moves**, per ADR 0015. There is no state in which a page has been renamed and its registration has not followed.
- **`fle`'s C1 gate stays non-blocking until the backfill lands.** P3.3 migrates all 349 front-matter marks with `registered_at: unknown-pre-programme`; the export supplies the real dates; that backfill is the release gate on making C1 blocking for `fle`. This is a hard dependency of P3.3 on this ADR and is the second reason the export is not optional.
- **The existing `efl` URL check does not substitute for any of this.** `_scripts/verify_url_parity.py` fetches the deployed *Quarto* sitemap and accepts a Hugo `aliases:` redirect as a valid destination — it verifies the reader's link, not the income — and it is `continue-on-error: true` at `efl/.github/workflows/hugo.yml:128` regardless. Its replacement is gate A3, keyed on `RelPermalink` against `url-lock.csv`.
- **This ADR is the reason several other decisions carry a "blocked" clause rather than a date.** ADR 0012's tag-term deletion and ADR 0017's topic reclassification are both analysed as URL-safe; neither may land on that analysis alone.

## Alternatives considered

**Generate `url-lock.csv` now from the sitemap crossed with `marks.yaml`, and reconcile against T.O.M. later.** Rejected, and this is the decision the ADR exists to record. The lock file is a baseline, and a baseline is not revisited once gates and pull requests are measured against it. Freezing against the sitemap would set gate A3 to defend URLs that no registration points at — permanently, and with a green check on exactly the divergence the gate exists to catch. A wrong baseline is worse than no gate, because no gate is visibly absent while a wrong one looks like coverage.

**Trust the `registered_at` dates already in the repositories.** Rejected. 399 of `efl`'s 402 predate the migration by six days, every one of them still carries a `qmd_path`, and the file's own header records that a script re-keyed the repository side. A date written by the side that could not reach T.O.M. is not evidence about T.O.M.

**Treat the `aliases:` entries as sufficient — the old URLs still resolve, so the marks still count.** Rejected on the mechanism, not on the policy. Hugo's alias output is a meta-refresh stub with no pixel in it; there is nothing to fire and nothing to verify, which is why the existing verifier skips those pages.

**Re-key all 592 questionable marks pre-emptively, without waiting for the export.** Rejected. It retires codes that may be perfectly sound, draws 592 new ones against a registration budget with real limits, and performs the most expensive action in the programme to avoid half a day of portal work that might show nothing is wrong.

**Proceed with URL-neutral work and defer the export until Phase 3.** Rejected. The export is already on the critical path of P3.3's `registered_at` backfill, so deferring it defers `fle`. And every month of delay is another month of possible forfeiture on up to 592 marks, which is the one cost in this programme that accrues while nobody is working.

**Ask the gate to accept either the registered URL or the rendering URL.** Rejected. That is the weakness of `efl`'s current verifier restated as a policy: a check that passes when a pixel appears *somewhere* cannot detect the exact failure — a page that moved and left its registration behind — that this ADR exists to find.
